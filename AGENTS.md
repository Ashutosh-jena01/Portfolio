# Beyond the Cloud — Development Rules

These rules apply to all work in this repository.

## Scope and approvals

- Implement only the currently approved phase.
- Never change the approved design pattern without explicit approval.
- Inspect existing code before making changes.
- Preserve previously working functionality.
- Stop after completing the assigned phase.
- Do not commit or push without explicit approval.
- Do not provision cloud infrastructure or deploy anything.

## Engineering standards

- Avoid unnecessary dependencies and overengineering.
- Use strict TypeScript typing.
- Follow modular, maintainable Python architecture.
- Manage database schema changes through Alembic.
- Review migrations before applying them.
- Never modify unrelated PostgreSQL databases.
- Ensure responsive design and accessibility.
- Respect `prefers-reduced-motion`.
- Optimize 3D rendering for device capabilities.

## Content and security

- Never expose credentials or commit environment files.
- Never fabricate professional achievements, skills or project outcomes.
- Use only approved professional content.
- Maintain asset licensing records.

## Documentation

- Update progress documentation after each approved phase.
- Keep architecture, design, animation and asset records aligned with the implementation.
